# Hooks

One row per Jev decision. The first column `id` must match entries in `decisions.json`; `tests/lib/check_bulma.py` fails when the two disagree. `graph/node` name the skill and the node where the hook fires. `state recipe` says what the orchestrator puts in the state JSON and how much (caps are character counts). `graph-answer` says what the graph's own rule would pick; pass it with `--graph-answer q=v` whenever it is cheap to compute, and always under `shadow`. `apply` says what to do when `act: true`; `act: false` always means use the graph's own rule. 

| hook | graph/node | fires when | state recipe | graph-answer | apply | outcome hook |
|---|---|---|---|---|---|---|
| `entry.route` | bulma / route | args are a PR or MR URL, `owner/repo#N`, or free text | `args`: raw text. `world`: `world.json` minus `prs[]` (keep `stack_top`, `jobs`, `states[]` trimmed by graph/status/waiting_user). `pr`: `world.json.pr` when a URL was given. `user_login`: `world.json.user` | none | `target` acted -> `load_graph` skill with `target_args`; `none` -> answer in chat and stop | none |
| `entry.next_step` | bulma / route | args empty or `resume` | `args`, `candidates`: `world.json.candidates[]` (id, target, why), `world`: same trim as above. `--criteria .ruver-bulma/candidates.json` decisive-yes | none | none | none |
| `fd.triage` | ruver-feature-delivery / triage | orchestrator evaluates ticket on first triage check | `goal` (one line), `ticket_title`, `ticket_body` (cap 3000), `acceptance_criteria` (one line each, cap 3000), `topology` (path list), `files_mentioned` (paths), `labels` | orchestrator's own triage | acted -> triage. Confidence `high` when `work_kind` + `path` + `risk` + `scope` all decisive, `medium` when within 0.10 of `act_at`, else `low`. `route_reason` cites `decision_id` | none |
| `policy.ask` | ruver-feature-delivery / grill (also any DECISION_POLICY fork, or lstm `unclear`) | orchestrator reaches a fork with two or more options it would consider asking about | `fork` (one sentence), `options` (list, each one line), `evidence` (paths, tracker facts, cap 3000), `recommendation` (one line), `acceptance_criteria` | DECISION_POLICY verdict `ASK` or `DECIDE` | ASK only when `important` and `uncertain` are both decisive-yes. Else DECIDE and write a `## Decisions` row with `Confidence:` from Jev | none |
| `qa.gate` | ruver-qa / execute | after the last planned step, per finding, before choosing `verdict` vs `request_triage` | `finding`: steps, expected, actual, evidence path (cap 4000). `pr.acceptance_criteria`, `pr.description` (cap 3000), `pr.files` (paths), `env_notes` | `FAIL` when VERDICTS.md items 1-5 hold, else `triage` | unambiguous FAIL only when two facts (`reproduced_twice`, `evidence_attached`) hold AND `violates_pr_ac` yes AND `in_changed_code` yes AND `env_or_flake` no, all decisive. Otherwise `request_triage`. Never PASS from Jev | none |
| `triage.classify` | ruver-triage / classify | per finding, before per-finding class row | `finding` (cap 4000), `reproducible` (yes/no/unknown), `pr.files`, `pr.hunks` (hunk headers only), `pr.description` (cap 3000), `open_issues` (id + title, max 10), `env_notes` | orchestrator's own class | acted -> class. Rollup by priority stays in `classify.md` | developer `apply_qa`: same finding id `PR_BUG` -> implement |
| `lstm.verify` | ruver-lstm / verify | every thread before author replies, unless `binding` already locked it in-scope | `comment` (cap 3000), `bound_path`, `bound_code` (cap 1200, 20 lines max), `neighbor_pattern` (cap 2000), `spec_bullet` (cap 500) or `policy.ask`). `reproducible`, `same_on_base` | orchestrator's own judgment | acted -> `bound_code_verdict` and `risk`. Append to verify.md report | user revises reply -> reverify this comment thread |
| `reviewer.failure_class` | ruver-reviewer / diagnose | orchestrator runs check-status and needs a class (log only, no PR comment yet) | `check_name`, `log_tail` (cap 200), `pr.files`, `reproducible` (yes/no/unknown), `mergeable` | orchestrator's own class | acted -> class in `failure_class` report and status line | user corrects class in chat -> `outcome <id> class reversed` |
| `review.risk` | ruver-code-review / critic | before critic engine runs `scripts/classify-risk.py` | `pr_title`, `pr_body` (cap 3000), `files` (paths), `changed_files`, `churn` | script's `high` / `low` | spawn high-risk critic when script says `high` OR Jev says `high` acted. Jev `low` changes nothing. Verdict phases untouched | none |

## State file

Write state JSON to `$RUVER_ROOT/.ruver-bulma/state/<hook>-<UTC ts>.json` and pass it with `--state`. Keep the file; humans read it if a decision looks wrong. Never put full files in it; observe caps and budgets.

## Context

Always pass `--context repo=<owner/repo> pr=<number> sha=<head> ticket=<id>` with what is known. Empty is fine.
